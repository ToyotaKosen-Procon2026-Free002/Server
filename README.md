# ココ・シール サーバー

GitHub Actions により、mainブランチにプッシュすると同時に本番環境へデプロイされます

[APIドキュメント](https://coco-seal.mydns.jp/docs)

## 通信の概要

### 通信の種類

- Flutterアプリとサーバー: **WiFi, Mobile**
  - ユーザー認証
  - 子機の設定や情報
- 子機とサーバー: **WiFi**
  - 主に子機がWiFi接続時に行われる
  - 子機のデータや設定の同期
- 親機とサーバー: **WiFi**
  - 親機のデータや設定の同期
  - すれ違った子機の情報送信
  - LoRaからの情報
- 子機と親機: **ESP-NOW, LoRa**
  - WiFiに接続できていない子機からサーバーへの情報送信の中継
  - すれ違い通信
- 子機と子機: **ESP-NOW, LoRa**
  - すれ違い通信
  - LoRaからの情報
- Flutterアプリと子機: **Bluetooth**
  - 主に初期設定時に使用する(WiFiの接続設定など)

### セキュリティ（暗号化と認証）

暗号化方式は特に言及がない場合、RSAを使用。

また、公開鍵認証にはECDSAを使用する。

1. **Flutterアプリとサーバー**

    主にFlutterアプリで使用されるアカウントはFirebaseが認証を行う。

    サーバーとの通信にはHTTPSが使用されるため通信経路も暗号化されている。

2. **子機とサーバー**

    WiFiに接続されているときに発生する通信であるため、HTTPSが使用される。

    サーバーには初期設定の時点で子機の公開鍵とデバイスIDを共有しておく。

    子機はデータに秘密鍵で署名を施し、サーバーが公開鍵で認証を行う。

3. **親機とサーバー**

    通信にはHTTPSが使用される。

    親機も子機と同様のプロセスで公開鍵認証を行う。

4. **子機と親機**

    子機は基本的に親機を信頼しない。

    すれ違い通信はやり取りする情報の機密性は低い（交換するシールのID、MACアドレス、すれ違いID、デバイスID、など）ため、ESP-NOWのデフォルトの暗号化のみで通信を行う。

    子機がサーバーに情報を送るために、親機を中継する場合は、子機の秘密鍵で署名を施したのちに、サーバーの公開鍵で暗号化を施し、親機に中継させる。

    また、データにリクエストID等を包含し、信号のリプレイを防止する。

    LoRaの場合は、署名のみを施す。（LoRaのデータの検証や詳細仕様は後述）

5. **子機と子機**

    子機と親機同様に、ESP-NOWデフォルトの暗号化のみで通信を行う。

    LoRaについても、署名のみを施す。

6. **Flutterアプリと子機**

    Bluetoothの通信方式にはGATTを使用する。

    まずはBluetoothを介して子機のWiFi接続設定を行う。

    WiFiに接続できたら、子機が直接サーバーにアクセスし、仮登録とワンタイムパスワードの発行を行う。

    OLEDにワンタイムパスワードのQRコードなどを表示し、スマホで読み取り、アカウントの紐づけと、子機の認証用公開鍵の登録を行い、これを本登録とする。

#### **LoRaのデータの検証について**

LoRaでデータを送信する場合、電子署名を施す。

しかし、検証用の公開鍵を所有しているのはサーバーのみであるため、その他の子機や親機はデータの検証を行えない。

そのため、直接LoRa通信を受け取った子機は、検証されていない通信としての表示と通知を行う。

WiFiに接続されている子機、もしくは親機はサーバーにLoRa通信の検証を依頼する。

検証結果を受け取った親機は周囲の子機に向けて検証結果を知らせる。

これによりLoRaデータが存在するアカウントのデバイスから発信されていることを検証できる。
